    OptionalclaimCache

    claimCache?: boolean

    Opt-in in-memory cache for hasClaim / hasClaims / getClaim / verifyPreset results. When true, a repeated read of the same wallet, credential type, threshold, trusted-issuer set and source is answered locally for SDKConfig.claimCacheTtlMs instead of hitting the RPC (or indexer) again. Disabled by default.

    Only successful reads are cached — a fail-soft false caused by an RPC error or missing configuration never is. A cached valid answer never outlives the credential's own on-chain expiry. After a submission you know about, call invalidateClaimCache; pass fresh: true on a read to skip the cache for that call.

    OptionalindexerCacheMs

    indexerCacheMs?: number

    How long indexer results for a wallet are reused, in milliseconds. Exists so a getClaims/hasClaims fan-out over N credential types issues one HTTP request instead of N. Set to 0 to disable. Only ever affects source: "indexer" and source: "indexer-verified" reads — chain reads are only ever cached by the opt-in SDKConfig.claimCache.
