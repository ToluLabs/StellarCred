Implementation Pattern: ProofRegistry's set_admin function
Source: contracts/proof_registry/src/lib.rs:343-361
Rationale: Proven production pattern, consistent approach across all contracts

Algorithm:
1. Load current admin from storage
2. Require admin authentication (require_auth)
3. Load current roles map
4. For each role held by old admin: transfer to new admin
5. Update both Admin and Roles storage keys
6. Emit EventAdminChanged event with timestamp
7. Return (atomic completion)
